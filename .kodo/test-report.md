## Critical Findings

### 1. Parallel(only infinite) completes immediately (US22)
**Severity:** High
**Description:** `Parallel` determines completion by checking if all *finite* children are done. If a `Parallel` contains ONLY infinite children (e.g., `Repeat(..., times=None)`), the condition is vacuously true. The `Parallel` action finishes in the first tick and calls `stop()` on its infinite children.
**Impact:** `Parallel(Repeat(A), Repeat(B))` does not run indefinitely; it stops both actions immediately.
**Repro:**
```python
s.do(Parallel(Repeat(Do(callback), times=None)))
game.tick(0.016)
# s._current_action is now None; callback ran only once.
```

### 2. ~~MoveTo speed=NaN propagates to sprite position (US8)~~ — FIXED
**Severity:** ~~Medium~~ Resolved
**Description:** Previously, `MoveTo` did not check if `speed` was a finite float. Passing `float('nan')` would corrupt the sprite position to `(nan, nan)`. As of commit `6b74177`, `MoveTo` now raises `ValueError` for `speed=NaN`, and also handles `speed=inf` safely (snaps to target).
**Status:** Fixed. US8 now passes.

### 3. on_exit exception blocks scene pop (US28)
**Severity:** Medium
**Description:** In `SceneStack._apply_pop()`, the `on_exit()` hook is called *before* the scene is removed from the internal `_stack`. If `on_exit()` raises an exception, the pop operation is aborted, leaving the "stuck" scene on top of the stack.
**Impact:** A broken scene can prevent the user from returning to previous menus or gameplay.
**Repro:**
```python
class CrashingScene(Scene):
    def on_exit(self): raise RuntimeError()
game.push(CrashingScene())
game.pop() # raises RuntimeError, stack still has CrashingScene
```
